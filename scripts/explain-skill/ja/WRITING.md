# やさしい日本語で書く

英語版のスキルは ASD-STE100（簡略技術英語）の80%で書きます。疲れた読み手でも、母語話者でなくても、1文を読みまちがえないようにするための規格です。日本語には同じ規格がないので、このファイルはその考え方を日本語に移したものです。もとにしたのは、STE の構造のルールと、出入国在留管理庁と文化庁の「在留支援のためのやさしい日本語ガイドライン」（2020年）の考え方です。英語で書くときは [STE.md](STE.md) に従います。

## まず、文章を分ける

| | 手順（何をするか） | 説明（それが何か、何をするか） |
|---|---|---|
| 文の形 | 「〜します」「〜してください」 | 「〜です」「〜します」 |
| 1文の長さ | 40字まで | 60字まで |
| まとまり | 1文に1つの操作 | 1段落に1つの話題、6文まで |

説明の文章は、ほとんどが「説明」です。「試してみる」「やり方」の部分は「手順」です。段落を分けて書きます。

## ルール

**言葉**
- 1つのものには1つの名前。用語集の言葉を選び、どこでも同じ言葉を使います。
- 外来語は用語集で1つに決めます（「リクエスト」と決めたら「要求」「呼び出し」と混ぜません）。
- 漢語を重ねすぎません。「設定変更実施」ではなく「設定を変えます」と書きます。
- 名詞を4つ以上つなげません。「接続プールのタイムアウトの値」のように「の」で分けます。

**動き**
- だれが動くかを書きます。「デーモンがリクエストを送ります」。受け身（〜される、〜られる）は、動く人がわからないときだけ使います。
- 動作は動詞で書きます。「圧縮を行う」ではなく「圧縮する」。
- あいまいな言い方をしません。「〜かもしれません」「〜と思われます」「〜と考えられます」の代わりに、事実を書くか、「〜できます」「〜します」と書きます。
- 二重否定（「〜ないわけではない」「〜なくはない」）を使いません。

**文**
- 1文に1つの新しい事実。
- 条件は先に書きます。「ビルドが失敗したら、ログを読みます」。
- 主語と述語を近くに置きます。長い修飾は、文を2つに分けます。
- 複雑な内容は箇条書きにします。
- 注意は、先に操作か条件、次に危険を書きます。「注意：本番環境で実行しないでください。行が消えます。」

**記号と数え方**
- 文末は「。」、区切りは「、」。ダッシュ「——」「―」と「；」は使いません。
- コード、識別子、ファイルのパス、単位つきの数、引用は、そのまま正確に書きます。文字数には入れません。
- 数字は算用数字（1、2、3）で書きます。

## 飾らない

やさしい言葉を使います（「活用する」ではなく「使う」）。前置き（「注目すべきは」）を書きません。誇張（「画期的な」「シームレスな」「強力な」）を書きません。3つ並べて水増ししません。

それが何をするかを、しくみか数字で書きます。どう感じるかは書きません。

## 渡す前のチェック

1. このスキルのフォルダから `python3 scripts/ja_lint.py <ファイル>` を実行します。1文の長さ、あいまいな言い方、二重否定、受け身、ダッシュと「；」、長い段落、誇張語を調べます。終了コード1は、直す必要のあるエラーです。
2. いちばん長い3つの文を声に出して読みます。2回読まないとわからない文は分けます。
3. 用語集の言葉の言いかえを探し、見つけたら用語集の言葉に直します。

## 合わないとき

このルールは、事実と手順のためのものです。広告の文章や個人的な文章を頼まれたら、このルールは合わないと伝えます。
