# explain

説明は、1つのテーマについて必ず2つで1組にします。どちらも同じ事実を、同じ言葉で教えます。

1. **文章**：返答の中の答えです。[WRITING.md](WRITING.md) の「やさしい日本語」のルールで書きます。英語で書くときは [STE.md](STE.md)（ASD-STE100 の80%）に従います。文章はページの横に置く要約でもあるので、読み手はページと見比べて確かめられます。
2. **ページ**：そのテーマを何も知らない人のための、1枚のELI5（5歳にもわかる）Webページです。デザインは「How does CCFT work?」バージョン1に合わせます。図は大きく、言葉は少なくします。図は自分で描かれ、3Blue1Brown風に動きます（[MOTION.md](MOTION.md)）。操作部品は shadcn の構造を v1 の色で使います（[SHADCN.md](SHADCN.md)）。ルールは [PAGE.md](PAGE.md) にあり、[templates/page.html](templates/page.html) から始めます。

ユーザーが片方だけを指定したとき（「文章だけ」「ページだけ」）は、その1つだけを作ります。答え全体が3文に収まるときは、文章を返し、ページは1行で提案します。

## 手順

1. **事実を集める。** 書く前に、コード、ドキュメント、資料を読みます。それぞれの主張に「確認済み」「推測」「仮定」のラベルを付けます。計画の中のすべての事実に出典かラベルがあれば完了です。
2. **先に用語集を書く。** テーマに必要な専門用語を並べ、それぞれにやさしい定義を1つと小さな例を1つ付けます。図である用語に色を付けたら、その色をどこでも使います。1つの意味には1つの言葉を使います（どこでも「リクエスト」。ある所では「リクエスト」、別の所では「呼び出し」とは書きません）。どちらの出力にも、用語集にない用語がなければ完了です。
3. **文章を書く。** [WRITING.md](WRITING.md) に従って書き、ファイルに保存して、このスキルのフォルダからチェックを実行します。
   ```bash
   python3 scripts/ja_lint.py <ファイル>
   ```
   英語の文章には `python3 scripts/ste_lint.py <ファイル>` を使います。終了コードが0になれば完了です。警告は、残す理由を言えるときだけ残します。
4. **ページを作る。** [PAGE.md](PAGE.md) に従ってテンプレートから作ります。ページの言葉にもチェックを実行します。PAGE.md のテスト項目がすべて通れば完了です。
5. **見せ物ではなく、確かめにする。** ページは答えを見せる前に、結果を予想させます。そのあと、前提を1つ変えて、新しい結果を見せます。各手順では、だれが動くかを書きます（「デーモンが送る」。「送られる」とは書きません）。
6. **届ける。** 返答に文章を書き、次にページを渡します。実行したチェックごとに、結果を1行で添えます。
