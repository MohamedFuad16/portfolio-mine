# Errors

- System `pdftotext` is not installed. Use bundled Python with `pdfplumber` for CV extraction.
- The shared `adr_index.sh` parser does not understand this repository's `## ADR-001 - date - title` headings; it leaves the date in the title and cannot read `Status:` from the following line. After running it, normalize the generated table manually unless the ADR heading format is migrated first.
- The agent-folder skill is installed under `~/.codex/skills/agent-folder/` in Codex; the `~/.claude/skills/agent-folder/` example path in its documentation may not exist. Resolve the scripts from the active skill directory before running graph or ADR helpers.
- React 19 warns when the boolean `inert` attribute is written as an empty string in JSX. Use `inert={true}` on the cloned mobile card face so it remains non-interactive without producing a console warning.
- The in-app Browser preview reports `document.hidden === true`, so `requestAnimationFrame` never fires: GSAP entrance tweens, CSS-driven beams and canvas orbs all freeze at their start state. Screenshots then look "broken" (invisible name/intro, `scale:0` timeline dots, empty contribution cells). Verify motion-dependent work by forcing end states in JS (`el.style.opacity='1'; el.style.transform='none'`) or by measuring geometry — do not conclude a rendering bug from a frozen frame.
- `.experience-summary` is `position: relative` to host the chevron's stretched hit area, which makes it the containing block for `.dot`. The dot's `left` is therefore the timeline offset (-26.5px) *plus* the summary's negative margin (12px desktop, 10px at <=560px). Change one and the other must follow, or the dots drift off the dashed line.
- BorderBeam's own `overflow: hidden` on `[data-beam]` does not reliably clip its blurred glow layer (`filter: blur()` child) in this engine — a filter-vs-overflow-clip compositing quirk. The bloom bled a colored smear past the avatar's rounded corner (worst on mobile, bottom-left). Fix: add `contain: paint` to `.avatar-beam` — stronger than `overflow: hidden`, forces every descendant (filtered or not) to clip to the box.
- `ContributionGrid` cells use `key={day.date || index}`. Fallback synthetic data and the real snapshot/API data commonly share recent date-string keys, so React reuses those DOM nodes across the swap instead of remounting — which means the cell-reveal ScrollTrigger's cached trigger position (measured against the fallback layout, before real data changed the section's height) never gets recalculated, and cells can be stuck permanently at their `opacity:0` "from" state. The existing `window.load` -> `ScrollTrigger.refresh()` doesn't cover this because the fetch typically resolves after `load` fires. Fix: refresh inside `ContributionGrid` in a `useEffect` keyed on `[cells, total]`, so it re-fires whenever the real data replaces the fallback.
- When verifying GSAP/ScrollTrigger-driven UI in the Browser preview pane, `scrollIntoView()`/`window.scrollTo()` calls made via `javascript_exec` do NOT reliably drive ScrollSmoother/ScrollTrigger the way a real scroll gesture does — some triggers never fire even though the element is visually in view. Use the `computer` tool's real `scroll` action (or a real click/tap) to test scroll-triggered reveals, not JS-dispatched scroll/scrollIntoView.
- `.avatar-shell` (sizes the border beam) and `.avatar` (sizes the visible photo) must never be resized independently — if only one gets a breakpoint override, the beam traces a box that no longer matches the photo, producing an offset/drifted glow on that breakpoint (exactly what happened at <=760px: `.avatar` shrank to 108px but `.avatar-shell` stayed at 120x124). Fix: `.avatar` and `.avatar-beam` are always `width:100%; height:100%;` and only `.avatar-shell` carries pixel sizes, so there is one sizing authority per breakpoint, not two that can drift apart.
- The project-card mobile expand/collapse animation measured its origin card's `getBoundingClientRect()` once at click time and stored plain numbers, then read them again later inside a `useGSAP` effect that only runs after `window.location.hash` triggers an async `hashchange` -> state update -> re-render round trip. GSAP ScrollSmoother's touch-flick momentum can still be settling the list during that gap — invisible to a synthetic click (which is instant), but reliably reproducible on a real phone flick-then-tap. Fix: re-measure the live card (`detailOriginCardRef.current.getBoundingClientRect()`) at the moment each animation (open AND close) actually builds, instead of trusting a stale click-time snapshot.
- The mobile detail overlay's `.pd-back` and `.pd-headline` carried both `pd-animate` and `pd-reveal`, while `.pd-shot` (the hero image) only ever carried `pd-animate`. `pd-reveal` elements are set to `{y:18, opacity:0}` and only tweened in later (stagger starting at t=0.25 in the open timeline), so the image appeared immediately while the back button and title popped in ~0.25s afterward — read as the header "settling"/glitching up and down after the image loaded. Fix: drop `pd-reveal` from `.pd-back` and `.pd-headline` so all three appear together with the rest of `pd-animate`; left `.pd-block` sections (below the fold) on `pd-reveal` intentionally.
- `ProjectFlowChart`'s connector arrows (`.fc-edge`) were completely invisible — not dim, not miscolored, literally not rendered. Root cause: every connector is a perfectly axis-aligned line (`M x y L x y2` or `M x y H x2`), so its SVG bounding box has zero width or zero height. The `#fc-sketch` hand-drawn-wobble filter used the SVG default `filterUnits="objectBoundingBox"`, whose `x/y/width/height` are percentages of that bounding box — a percentage of zero is zero, so the filter region collapsed to a degenerate rect and the browser rendered nothing for any element using it. The boxes/diamonds have real bounding boxes so they were fine; only zero-area shapes (straight lines) broke. Fix: `filterUnits="userSpaceOnUse"` with a fixed pixel region sized to the SVG's own `width`/`height` (plus margin), so the filter region no longer depends on the filtered element's own bbox. General rule: never leave an `objectBoundingBox` filter (the default) on an element that can have a zero-width or zero-height bounding box — switch to `userSpaceOnUse` with an explicit region instead.
- A media query that changes `.experience-summary`'s negative margin and one that changes `.dot`'s `left` are coupled: the dot offset is `lineCentre - itemLeft + summaryOverhang - 8`. The `<=760px` block set `left: -25.5px` (the no-overhang value) while the overhang was still 12px until `<=560px`, so every dot sat 12px off the line for that whole band and nobody noticed because the two checked breakpoints (desktop and 375px) both happened to be correct. When touching either rule, measure at 700px as well — and prefer `offsetLeft` chains over `getBoundingClientRect()`, since a frozen GSAP `scale(0)` collapses the rect but leaves layout position intact.
- The contribution grid's month header only means anything if a grid column is a week. While the grid flowed row-major in 35-day rows, the labels were decoration sitting above unrelated days. It is now `grid-auto-flow: column` with 7 rows, and both the header and the grid read the same `--grid-columns` custom property off `.calendar-scroll`; keep `CONTRIBUTION_WEEKS` (src/main.jsx) and `DAYS` (scripts/fetch-contributions.mjs) in sync or the header and the data drift apart.
- `element.focus()` is silently a no-op while the element is `visibility: hidden`, which is exactly what GSAP's `autoAlpha: 0` sets. Anything that focuses into a GSAP-animated overlay must wait for the computed `visibility` to flip rather than using `setTimeout(0)` or a guessed delay — the open timeline can outlast any fixed guess.
- `window.history.length > 1` does not mean the previous history entry belongs to this site; it only means the tab has history. Never use it to decide whether `history.back()` is safe — track whether the app itself pushed the entry.
- Vite 8 bundles rolldown, which needs Node `^20.19.0 || >=22.12.0`. The default `node` on this machine is 20.11.0, so every Vite command fails with `SyntaxError: ... 'node:util' does not provide an export named 'styleText'`. Use `PATH=/opt/homebrew/bin:$PATH` (Node 25) or `nvm use`.
- The in-app Browser pane can stop repainting entirely (screenshots come back solid black, `computer` actions time out with "The Browser pane is currently hidden"). DOM measurement via `javascript_exec` keeps working when this happens — fall back to it rather than concluding the page is broken. Related: because `document.hidden` is true, `requestAnimationFrame` never fires, so GSAP timelines never complete and any `onComplete` (for example the detail overlay's unmount) never runs. To exercise rAF-dependent app code, shim `window.requestAnimationFrame` onto `setTimeout` before triggering it; GSAP's own ticker captured the real rAF at load and will stay frozen regardless.
- Chrome's `--headless --screenshot --virtual-time-budget=N` fast-forwards timers, which breaks Firebase auth initialisation and captures SPAs on their "Loading…" frame. For a real screenshot, drive the DevTools protocol instead: `Page.navigate` → wait for `Page.loadEventFired` → settle a few seconds → `Page.captureScreenshot`, with `Emulation.setDeviceMetricsOverride` at `deviceScaleFactor: 2` for the 1440x810 preview convention.
- Project previews are not all PNGs despite the `.png` names — several are JPEG bytes with a `.png` extension. When adding a preview, pick the format by content: JPEG for light gradient-heavy UI, PNG (quantized to 256 colours) for dark screenshots of small monospace text, where JPEG rings badly around glyphs.
- `project.github` is optional. A project whose repo is private renders a "Private repo" label instead; never emit a link to a private repository URL, since it 404s for every visitor.
- The `#fc-sketch` turbulence/displacement filter that was supposed to give the flow chart a hand-drawn wobble was **invisible**: filtered and `filter: none` renders came out pixel-identical at 3.2x magnification (max channel delta 0). `baseFrequency 0.02` varies over ~50-unit periods and `scale 2.4` displaces by at most ~1 unit, which rounds away at the rendered scale. The chain worked — swapping in `feGaussianBlur stdDeviation=6` blurred everything, and `scale=18` crinkled it visibly. General rule: a displacement filter subtle enough not to look noisy is usually subtle enough to be invisible; do hand-drawn looks as perturbed path geometry, not as a post-process filter. Removed in ADR-044.
- When judging rendering quality, do not trust the un-magnified preview pane. Capture a clipped, magnified screenshot over CDP (`Page.captureScreenshot` with a `clip` and `scale: 3`) and diff the variants with Pillow — that is what turned "the drawing feels off" into a measurable zero-delta finding.

- GSAP's default unit is **not** px for every CSS property. `gsap.set(el, {minHeight: 404.75})` writes `min-height: 404.75%`, not `404.75px`, while `{width: 350}` does write `350px`. Pass explicit `${n}px` strings for anything other than the common transform/dimension props, and verify with `getComputedStyle` rather than assuming — this silently made the expand-clone 3121px tall (ADR-046).

- `getBoundingClientRect()` returns the **post-transform** box. While the project overlay is open, `main` sits at `scale(0.95)`, so measuring the origin card during the close returned its scaled rect and the close animated to a target 53px too high and 17px too narrow. `measureOrigin()` now neutralises `main`'s inline transform for the measurement and restores it (reading a rect forces layout but never a paint, so nothing flashes). Never use `getBoundingClientRect` to answer "where will this be once the transforms finish" (ADR-047).
- `background-clip: text` clips to the glyphs of the element it is set on, so a shimmer must live on its own span — putting it on a flex parent would also blank any non-text sibling via the inherited transparent `-webkit-text-fill-color`. Always pair it with a `background-color` in the base tone: that is clipped to the glyphs too and keeps the text legible if the gradient ever fails to paint, instead of leaving it invisible.
